# hayaoshi-quiz 実プレイ検証(ボット)

このプロジェクトのサーバーロジック(`room.js`/`server.js`/`gameData.js`)は、タイマーと状態遷移が複雑に絡み合っている(`room.js`のコメント参照)。コードを目で追っただけでは見落としが起きやすいので、`socket.io-client`で実際に接続するボットスクリプトを書いて動かし、狙った通りに動くことを確認する。[[feedback_verify_dont_guess]] の方針をこのプロジェクトに適用したもの。

## 手順

1. **ポート3000が空いているか確認する**(Windows: `Get-NetTCPConnection -LocalPort 3000 -State Listen`)。[[feedback_windows_stray_server]] の通り、前回の起動が残っていることがある。
2. `npm install --no-save socket.io-client` で一時導入する(既に入っていれば不要)。
3. `node server.js` をバックグラウンドで起動し、`早押しクイズサーバー起動: http://localhost:3000` のログが出ることを確認する。
4. **検証用ボットスクリプトはプロジェクト直下(このフォルダ)に置く**。scratchpadに置いて実行すると `Cannot find module 'socket.io-client'` で失敗する(Node.jsの`require`はスクリプト自身の場所を基準に解決するため、cwdやNODE_PATHとは無関係)。ファイル名は `_test_*.js` にして、後で確実に見分けて削除できるようにする。
5. スクリプトを実行し、結果を確認する。
6. **必ず後片付けする**:
   - `_test_*.js` を削除
   - `npm uninstall socket.io-client`
   - サーバープロセスを止める(`Get-Process node | Stop-Process -Force` は他のnodeプロセスも巻き込むので注意。可能なら起動時に控えたPIDだけ止める)
   - ポート3000が再び空いていることを確認する
   - `git status --short` で意図しない変更が残っていないか確認する

## ボットスクリプトの書き方のコツ

- **正解を知る方法**: クライアントに送られる`state`には答えそのものは含まれない(それが仕様)。ボット側で `require('./gameData').questionBanks` を直接読み込み、届いた`state.question`(問題文)と突き合わせて`input`(正解の判定文字列)を調べる、という「サーバーと同じデータを直接覗く」やり方でよい(本番のクライアントがやる不正ではなく、あくまでテスト用の近道)。
- **リスナー登録とイベント発火の順序**: `socket.once('state', ...)` を先に登録してから対応する `emit` を行うこと。逆にすると、発火直後に届く肝心の`state`を取りこぼし、無関係な後続の`state`を誤って掴んでしまう(このプロジェクトで過去に2回、この順序ミスがテスト失敗の原因になった)。
- **フェーズを待ってから操作する**: 例えば早押し(`player:buzz`)は`phase !== 'open'`の間は無視されるだけでエラーにもならない。「問題が来たらすぐ押す」ではなく、`state.phase === 'open'`になったのを確認してから`emit`する。
- 共通の待機ヘルパーとして、`state`イベントに対する述語(predicate)付きの`Promise`ラッパー(タイムアウト付き)を書いておくと、フェーズ遷移待ちが読みやすくなる。

## これまで検証してきた観点(変更内容に応じて取捨選択する)

- 1人でのフルラウンド(参加→開始→早押し→全文字正解→次の問題)
- 複数人での同時早押し(押した本人だけ`letterChoices`が届くか)
- CPU対戦相手(正解パス・わざと間違えるパスの両方)
- 誰も押さない場合のタイムアウトからの自動進行
- 早押し中の切断→猶予時間内の再接続でスコアが復元されるか
- ラウンド途中での`game:end`即時実行(タイマーが確実に止まり、直後の`game:start`が正常に動くか)
- 先取点数・出題数上限に到達したときに、演出(正解発表・問題文の続き表示)を最後まで見せてから`gameOver`になるか。ゲーム中は設定変更が反映されないか
- `join`前の接続でも`state`が届くか(全員配信の挙動)

## 適用範囲

このスキルは hayaoshi-quiz プロジェクト専用(このフォルダの `.claude/skills` 配下)。他のアプリでは使わない。複数アプリ共通の「第三者チェック」の枠組みが必要な場合は、`third-party-review` スキル(アプリ開発フォルダ直下、全アプリ共通)を使う。
